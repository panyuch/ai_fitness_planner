# 03: AI 受控选材闭环

**What to build:** AI 模式下，LLM 只从本地食材库候选清单里挑选每餐食材（受控选材），服务端校验全部食材合法后由算法引擎按宏量目标分配分量——生成结果全部是库内常见食材、宏量依然准确达标。已锁定餐次会告知 LLM 以便避让，生成后仍以本地锁定内容覆盖；LLM 输出含库外食材或结构异常时整体回退本地，绝不产出坏结果。

## 连通性实测（2026-08-30，复刻 callAI 直测本机 Ollama）

- **受控选材协议（仅 id 输出）**：HTTP 200，**60.6s（<90s 超时）**，AI 返回 7 天 × 4 餐结构（对比全量协议 206s + 截断）。
- **容错决策**：qwen3 偶发输出缺 `id` 字段的残缺项——`resolveAIIds` 对「库外 id」整体抛错回退（防幻觉食材），对「缺 id 残缺项」忽略（保证结构正确时可用），全餐无有效食材才回退。
- **组装结果**：周蛋白 1155.8g（目标 1155，偏差 0.07%）、最大热量偏差 **0.13%**（容差 2.6%）——AI 选材 + 算法定克数闭环成立，食材全部库内常见食材（实测第 1 天早餐：鸡胸 102g + 米饭 209g + 西兰花 150g + 橄榄油 15g）。
