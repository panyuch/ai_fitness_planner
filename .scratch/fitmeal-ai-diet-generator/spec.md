# FitMeal AI 饮食计划生成器 — 产品规格说明书 (SPEC)

> 版本：v1.0 · 更新：2026-08-22  
> 定位：**求职作品集 Demo**（非商业、不变现）  
> 技术栈：Next.js 14（App Router）全栈 + 本地营养计算引擎 + 可选国内 LLM

---

## 1. 项目概述

### 1.1 定位

一个面向**健身 / 运动 / 运动员备赛人群**的 AI 周饮食计划生成器。用户输入身体数据与训练信息后，由系统计算出每日热量与三大宏量营养素目标，并生成一份**按训练日 / 休息日分化的 7 天饮食计划**（含每餐食材、克数、宏量）。

### 1.2 目标用户

- 进阶健身者、力量 / 体能训练爱好者、有备赛（cut / 增肌）需求的人群。
- 关注「饮食是否科学、接近专业营养师口径」的用户。

### 1.3 价值主张（Demo 视角）

- 计算逻辑**透明可见**：结果页展示 BMR / PAL / TDEE / 宏量 / 训练分化等"计算依据"，而非黑盒输出。
- 算法基于**最新文献公式**（Henry 2005 BMR + 标准 PAL + 国际蛋白摄入建议），并内置备赛护栏。
- 全部营养计算在**本地完成**，无运行时外部依赖、不收集用户数据。

### 1.4 非目标（明确边界）

- 不提供登录 / 账号 / 多用户 / 云端存储。
- 不提供医疗或临床营养建议（见 §9 免责声明）。
- 不内置补剂推荐模块（设计阶段已主动移除）。
- 当前阶段不变现、不接支付。

## 3. 信息模型（输入）

用户输入分四组，对应表单字段：

### 3.1 基本信息

| 字段        | 类型                | 说明                        |
| --------- | ----------------- | ------------------------- |
| `sex`     | `male` / `female` | 性别（影响 BMR 方程）             |
| `age`     | number            | 年龄（影响 BMR 年龄分组）           |
| `height`  | number            | 身高 cm（预留，当前计算未直接用于 BMR）   |
| `weight`  | number            | 体重 kg（BMR / 蛋白 g/kg 核心输入） |
| `bodyFat` | string（可选）        | 体脂率，留空不阻断计算               |

### 3.2 目标与周期

| 字段              | 取值                          | 说明                |
| --------------- | --------------------------- | ----------------- |
| `goal`          | `cut` / `bulk` / `maintain` | 减脂 / 增肌 / 维持      |
| `timelineWeeks` | number                      | 周期周数（影响缺口 / 盈余封顶） |

### 3.3 训练与活动

| 字段           | 取值                              | 说明                 |
| ------------ | ------------------------------- | ------------------ |
| `trainFreq`  | 0–7                             | 每周训练频率（驱动排程 + PAL） |
| `splitType`  | string（如「推拉腿(PPL)」）             | 分化类型，用于展示文案        |
| `intensity`  | `low` / `mid` / `high`          | 训练强度，用于展示文案        |
| `workType`   | `sedentary` / `light` / `heavy` | 工作性质（影响 PAL）       |
| `steps`      | number                          | 日均步数（展示用，预留）       |
| `cardioFreq` | number                          | 每周有氧次数（影响 PAL）     |

> 注：表单字段名 `cardioFreq` 与引擎入参 `cardio.freq` 已做兼容（`computePAL` 同时读取二者）。

## 4. 营养计算引擎（`lib/nutrition.js`）

### 4.1 基础代谢率 BMR — Henry (2005) / Oxford 方程

按年龄分组的体重线性方程（kcal/天），来源 Nutrients 2023 Table 1：

| 性别 | 18–30        | 30–60        | 60+          |
| -- | ------------ | ------------ | ------------ |
| 男  | 16.0·W + 545 | 14.2·W + 593 | 14.2·W + 593 |
| 女  | 13.1·W + 558 | 9.74·W + 694 | 9.74·W + 694 |

（W = 体重 kg）

### 4.2 活动系数 PAL

- 训练频率：`≥6 → 1.725`，`≥3 → 1.55`，`≥1 → 1.375`，`0 → 1.2`
- 工作性质：`heavy +0.15`，`light +0.05`
- 有氧：`min(0.1, cardioFreq × 0.02)`
- 钳制区间 `[1.2, 1.9]`

**TDEE = BMR × PAL**

### 4.3 阶段热量（目标缺口 / 盈余）

| 目标         | 周期 ≤8 周    | 周期 >8 周         |
| ---------- | ---------- | --------------- |
| `cut`      | −20%（缺口封顶） | −15%            |
| `bulk`     | +12%       | +10%（盈余封顶 +15%） |
| `maintain` | 0          | 0               |

> 备赛护栏：减脂缺口封顶 −20%，避免代谢损伤与肌肉流失。

### 4.4 宏量营养素分配

- **蛋白**：`cut 2.2` / `bulk 2.0` / `maintain 1.8` g/kg（取整到整数 g）。
- **脂肪**：按目标占比（见下表）。
- **碳水**：作为剩余项补足（kcal − 蛋白 kcal − 脂肪 kcal）。

碳水 / 脂肪占比（轻量碳循环：训练日高碳、休息日低碳）：

| 目标         | 训练日 carb / fat | 休息日 carb / fat |
| ---------- | -------------- | -------------- |
| `cut`      | 45% / 25%      | 30% / 35%      |
| `bulk`     | 50% / 22%      | 40% / 30%      |
| `maintain` | 45% / 28%      | 35% / 33%      |

- 休息日热量：减脂目标下取阶段热量的 **95%**（进一步放大碳循环幅度），其余目标等同阶段热量。

### 4.5 备赛充碳周提示（peak week）

当 `goal === 'cut'` 时生成文字提示：

- 赛前 1 周先做 2–3 天碳水耗竭（约 **1 g/kg**，即 `体重×1` g/天）；
- 赛前 1–2 天充碳至约 **4.5 g/kg**（即 `体重×4.5` g/天）并同步调整水分；
- 水 / 钠（脱水）调控属高风险操作，**仅提示、不在工具内一键执行**。

共 **29 种**，按类别分池（`POOLS`）：

## 6. 周计划生成算法（`lib/generator.js`）

### 6.1 训练日排程 `buildSchedule(trainFreq)`

按频率返回 7 位 0/1 数组（1=训练），模式表保证训练日分布且穿插休息：

- 5 练示例 → `[1,1,0,1,1,0,1]`（即 `1101101`）。

### 6.2 餐次拆分

每天 4 餐，占全天比例：

- 早餐 `0.25` / 午餐 `0.35` / 晚餐 `0.30` / 加餐 `0.10`

### 6.3 单餐宏量分配 `buildMeal`

每餐由 **主蛋白 + 碳水 + 蔬菜(固定 150g) + 健康脂肪** 四项组成。采用  
**「初值估算法 + 定点迭代（4 轮）」** 使全天达标：

1. 以"主蛋白承担全天蛋白"为初值，算出碳水 / 脂肪克数；
2. 每轮扣除蔬菜 + 碳水 + 脂肪的**天然蛋白**，反推主蛋白真实需求；
3. 把主蛋白少用的热量回填到碳水 / 脂肪，重算二者克数；
4. 4 轮后收敛：全天蛋白 ≈ 目标，全天热量贴近目标。

**实测精度**：训练日均热量偏差 ≤2.6%、休息日 ≤2.6%、周蛋白总和偏差 ≤1%（以 26 岁男 / 75kg / cut / 5 练 为例：BMR 1745、PAL 1.59、TDEE 2775、训练日 2220 kcal、休息日 2109 kcal、蛋白 165 g/天）。

### 6.4 锁餐（lock）

`locked` 以 `{ "3-lunch": <mealObject> }` 形式传入；重生成时跳过被锁餐次，其余重新生成 —— 实现"锁定某一餐、重排其他"。

## 7. AI 集成（`app/api/generate/route.js` + `lib/prompt.js`）

- 接口 `POST /api/generate`：接收 `{ input, locked }`，返回 `{ calc, plan, usedAI }`。
- 引擎探测顺序：`DEEPSEEK_API_KEY` → `DASHSCOPE_API_KEY`（通义）。命中则调用对应 chat completions，按 `lib/prompt.js` 构造的 system/user 提示词 + JSON Schema 产出计划。
- **无 key 或调用失败** → 自动回退本地 `generateWeek`（兜底 + 容错）。
- `usedAI` 字段告知前端实际走的是 AI 还是本地引擎。

## 8. 结果页与交互（`app/page.js`）

- **输入表单**（左栏）：§3 全部字段的可点击选项卡片式录入（用户偏好，非纯文本）。
- **计划展示**（右栏）：7 天 × 4 餐，每餐列出食材 + 克数 + 宏量；全天宏量汇总条（蛋白绿 / 碳水蓝 / 脂肪琥珀）。
- **原理展示（Principle）**：可展开面板，显示 BMR 公式、PAL、TDEE、阶段热量、蛋白 g/kg、训练 / 休息日宏量、备赛充碳提示——呼应"透明可解释"卖点。
- **一键重生成**：保留或清空锁餐后重新生成整周。
- **锁餐**：单餐锁定时图标标记，重生成不被覆盖。
- **语言**：全中文界面。

## 9. 导出与免责

- **导出**：一键下载 **Markdown 完整版**（周计划 + 每日宏量 + 计算依据 + 免责声明）。

## 12. 运行方式（重要）

本沙箱 Node 被注入 `genie-safe-delete` 安全删除包装，会使 `next dev` 因回收站不可用而崩溃。运行前务必清空该注入：

```bash
cd D:\working\fitness
NODE_OPTIONS="" npm run dev
# 浏览器打开 http://localhost:3000
```

启用 AI 模式：设置 `DEEPSEEK_API_KEY` 或 `DASHSCOPE_API_KEY` 后重启 dev server 即自动切换。

## 13. 已知限制 / 后续迭代

1. **生成器餐次仅组合 4 类**：目前每餐 = 主蛋白 + 碳水 + 蔬菜 + 脂肪；`fruit` / `dairy` 池已建库但**尚未接入餐次生成**（可作为加餐候选）。
2. **身高 `height` 已接入 BMR**（ticket 12）：填了有效身高时引擎自动改用 Mifflin-St Jeor（含身高，更精确），未填则回落 Henry 2005；界面不暴露方程选择，由系统按身高自动决策。
3. **`steps` / `intensity` 已进入 PAL 计算**（ticket 13）：步数→NEAT 加成、训练强度有加成；`splitType` 仍仅用于展示文案。
4. **本地生成器为启发式**：非 LLM，食材搭配较固定；AI 模式（需 key）可产出更自然的组合。
5. **未做持久化**：刷新即丢失，无保存 / 历史记录。
6. **跨会话源码曾被沙箱误删**：强烈建议对 D:\working\fitness 做版本管理（如 `git init`）或定期备份。
