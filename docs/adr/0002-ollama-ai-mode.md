# ADR 0002 — 接入本地 Ollama qwen3 的双模式生成架构

- 状态：已采纳（2026-08-30，`/grill-with-docs` 访谈共识）
- 关联：`.scratch/ollama-ai-mode/spec.md`

## 背景

v1.0 生成器（`lib/generator.js`）是纯确定性函数：同样的输入与锁餐必然产出相同计划，导致结果页「重生成」/「清空锁餐重生成」点击后结果不变，用户感知为"按钮没反应"。用户希望接入本地 Ollama 的 qwen3 模型生成更自然的饮食计划。经多轮设计树访谈锁定双模式架构。

## 决策

1. **双模式可切换**：默认走算法引擎；表单区提供「AI 生成」开关，开启后生成改走本地 LLM（Ollama qwen3:8b）。Ollama 官方库无 "qwen-3.5" 模型，qwen3 为当前主线。
2. **LLM 受控选材**：AI 模式下 LLM 只能从本地食材库候选清单（`lib/foods.js`）中挑选食材 id，不得发明库外食材。
3. **算法定克数**：LLM 只决定"每餐吃什么"，分量仍由 `buildMeal` 按宏量目标定点迭代分配，营养数字 100% 由算法保证。LLM 幻觉被隔离在选材层。
4. **锁餐告知 LLM**：提示词附带已锁定餐次摘要，LLM 围绕剩余餐次搭配；生成后仍以 `overlayLocked` 覆盖锁定餐。
5. **算法模式随机化**：生成器支持可注入 seed——首次生成固定 seed（结果与现状一致、演示可复现），重生成时前端传新 seed；食材同类池轮换 + 分量 ±10% 份额扰动后收敛（锚定碳脂热量份额，初值抖动会被迭代抹平），仍保证宏量达标。
6. **降级与提示**：LLM 失败/超时（90s）回退算法引擎，结果页明示「本次由本地引擎生成」，避免再现"点了没反应"的困惑。
7. **调用参数**：qwen3 禁用 thinking（`enable_thinking: false`），避免输出夹杂思考过程破坏 JSON 解析。
8. **接入点**：`lib/prompt.js` 的 `PROVIDERS` 增加 ollama 项（baseURL `http://localhost:11434/v1/chat/completions`，OpenAI 兼容协议，零新运行时依赖）。Ollama 为本机外部服务，不随项目打包。

## 被否方案

- **LLM 全权生成**（替代算法引擎）：改动最小但本地小模型算的克数/宏量易幻觉，与产品"计算透明、营养准确"的定位冲突。
- **LLM 定克数 + 服务端回算**：允许 LLM 自由定分量、服务端回算宏量并后校验。搭配更自由但可能不达标、需额外修正逻辑；最终选择让算法继续分配分量，精度与改动量双优。
- **算法保持确定性**：重生成"无变化"的体感问题未真正解决，被"加随机 seed"取代。

## 后果

- 正向：重生成在两种模式下都可见变化；AI 模式数字仍 100% 达标；零新增运行时依赖。
- 负向/注意：本地 8b 生成需 30-90s，等待体验依赖 90s 超时 + 前端进度提示；单测确定性依赖可注入 seed（默认固定）；Ollama 未运行时 AI 开关无意义，需降级提示兜底。
