# ADR 0001 — FitMeal UX Round 关键决策

- 状态：已采纳（2026-08-28）
- 关联：`.scratch/fitmeal-ux-round/spec.md`

## 背景

FitMeal v1.0 已端到端跑通，但作为求职 Demo 体感"未完工"。经 `/grilling` 多轮对齐，确定本轮做聚焦 UX 补课。以下为过程中出现的、不易回退的设计决策。

## 决策

1. **历史保存触发 = 手动**。grilling 中用户先选"每次生成自动存"，后翻转为"手动「保存此计划」按钮"。最终定为手动，保留用户对"什么值得留存"的掌控感，也避免连点产生噪音。
2. **历史存储 = 本地 localStorage，上限 20 条 + FIFO 淘汰 + 旧结构迁移**。不引入后端/账号；兼容迁移旧 `STORE_KEY` 单计划结构，防止老用户数据丢失。
3. **结果页「计算依据」默认折叠，常驻一句结论（目标+周期 + TDEE+每日热量）**。降低新用户压迫感，同时保留可展开透明性（方程名/宏量占比在展开区）。
4. **不动营养算法与 API**，UX 改动全部在 UI 层与新增 `lib/history.js` 内完成。

## 后果

- 正向：范围可控、可单测、不污染 v1.0 引擎；用户体验闭环补齐。
- 负向/注意：手动保存意味着用户若不主动存，仍会"用完即丢"——需在 UI 上让"保存"显眼、并在首次向导中说明。
- 不做：移动端响应式、分享图片、进度追踪、算法改动（留作后续 round）。
